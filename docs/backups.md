# 加密备份与恢复

备份是与数据库驱动无关的应用级逻辑归档，不是 SQLite/MySQL 双写，也不是数据库文件副本。归档包含用户、加密后的连接凭据、服务器、任务、操作、审计、控制台会话和非敏感设置；不包含运行时凭据主密钥和备份口令。

## 创建与保管

在“备份与设置”中输入至少 12 个字符的独立口令。应用使用 scrypt 派生 256 位密钥，再用 AES-256-GCM 对版本化 JSON 快照执行认证加密。每份归档使用随机 salt 和 nonce，并记录密文 SHA-256、格式版本、大小与记录数量。

口令仅存在于本次请求内，不写入数据库、文件名、审计或浏览器持久存储。丢失口令无法恢复归档。连接凭据在归档中仍是由 `CREDENTIAL_KEYS` 加密的密文，因此恢复环境还必须配置原来的凭据主密钥；只持有备份口令并不足以解密服务商凭据。

`BACKUP_DIRECTORY` 默认是 `data/backups`；Compose 默认挂载独立的 `/backups` 卷。目录和文件分别使用 `0700` 与 `0600` 权限。生产环境应把备份卷复制到独立、受控和有版本保留的存储中。

## 校验与恢复

校验会检查文件大小、SHA-256、加密认证、格式版本、逻辑表清单、列模式、记录数量和字段类型，不修改当前数据库。

恢复要求当前没有排队或执行中的任务及电源操作。流程为：

1. 完整校验选中的归档和口令。
2. 使用同一口令创建当前状态的安全快照。
3. 在单个数据库事务中按外键顺序替换逻辑数据。
4. 写入不含口令的恢复审计事件。

恢复会替换用户和 Session，因此当前登录随后失效。安全快照元数据和文件不包含在被替换的数据集合中，可用于人工回退。SQLite 与 MySQL 之间迁移必须通过这一流程，并在目标环境配置相同的 `CREDENTIAL_KEYS`。

下载接口只返回已加密的 `.scpb` 文件并使用 `Cache-Control: no-store`。不要修改文件内容或扩展名；任何篡改都会使认证或校验和验证失败。
