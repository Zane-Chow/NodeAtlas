# 电源操作与实时更新

当前版本支持对单台服务器执行开机、关机和重启。控制台、VNC/串行连接、服务商后台回退以及备份功能尚未开放。

## 操作条件

界面根据本地最近一次同步的状态和服务商能力决定按钮是否可用：

- 开机：服务器为 `stopped` 或 `suspended`，且 `can_start` 可用。
- 关机：服务器为 `running`，且 `can_stop` 可用。
- 重启：服务器为 `running`，且 `can_reboot` 可用。

能力不可用时按钮保持禁用，其 `title` 包含服务商返回的原因。每次操作都必须在确认对话框中再次确认。服务端会重新执行相同的状态与能力校验，因此过期界面不能绕过限制。

同一台服务器同时只允许一个非终态操作。数据库唯一约束在 SQLite 和 MySQL 中共同保证这一点；冲突请求返回 HTTP `409` 和 `active_operation`。

## 幂等性

`POST /api/v1/servers/{server_id}/actions/{start|stop|reboot}` 接受 `Idempotency-Key` 请求头。Web 客户端为每次确认生成 UUID。相同键重放时返回原操作，不会再次排队或重复调用服务商。

若调用方不提供幂等键，服务端会生成一个，但 API 集成方应自行生成并保存该键，直到收到明确响应。请求头最大长度为 255 个字符。

## 执行、重试和验证

持久化工作器在写操作前重新读取远端状态。开机目标已经运行或关机目标已经停止时，操作直接成功，不再调用写接口；重启始终调用服务商。

默认最多尝试 3 次。服务商网络错误、限流和明确标记为可重试的错误使用指数退避（1 秒起步，最长 5 分钟）；认证、权限、无效配置、不支持和未找到等错误直接失败。服务商接受写操作后，工作器默认每 2 秒读取一次状态，最长验证 2 分钟。

操作状态含义：

- `queued`：已持久化，等待工作器领取。
- `running`：工作器正在检查连接和远端状态。
- `verifying`：服务商已接受操作，正在验证目标状态。
- `succeeded`：目标状态已确认并更新本地服务器索引。
- `failed`：终态失败，详情中包含清理后的错误码和信息。
- `timed_out`：在验证窗口内没有达到目标状态。
- `cancelled`：保留的终态，当前界面尚未提供取消操作。

排队、成功、失败和超时均写入只追加的审计日志。审计元数据仅包含操作类型和状态，不记录凭据、令牌、Cookie 或服务商原始响应。

## 实时事件

已登录客户端连接 `GET /api/v1/events`。服务端通过 Server-Sent Events 发送 `operation.updated` 和 `server.updated`，载荷仅包含操作 ID、服务器 ID 与状态等失效提示；客户端收到后重新读取 REST API 中的权威数据。事件每 15 秒发送一次心跳，断线后浏览器按 3 秒提示自动重连。

反向代理必须：

- 保持长连接并将读取超时设置为明显大于 15 秒；
- 禁用该路径的响应缓冲与缓存；
- 保留会话 Cookie，不将 `/api/v1/events` 暴露为匿名端点；
- 支持响应流即时刷新。应用同时返回 `X-Accel-Buffering: no`，但仍应在代理层显式关闭缓冲。

SSE 是进程内通知通道，不保存历史，也不是权威状态来源。客户端重连后依靠 REST 刷新，因此丢失单个事件不会丢失操作记录。
